# NBTI 产品定位简版

## 这份文档回答什么

这份文档只回答一个问题：

> **NBTI 在整个 VisionTree 中起什么作用？**

旧定位是“引流入口”：用趣味测试吸引用户，再把用户带到 VisionTree。这个定位容易理解，但 NBTI 自身价值较弱，也没有回答用户为什么要从测试继续进入主产品。

## 版本一：流量入口

**定位：** NBTI 是 VisionTree 的营销产品，用低门槛测试获得传播和新用户。

```text
趣味测试 → 分享传播 → 认识 VisionTree → 进入 Hub
```

**优势：**

- 团队容易理解，路径最短；
- 可以最大限度保留现有测试和报告页；
- 成功标准直接，主要看完成、分享和导流。

**问题：**

- NBTI 与普通人格测试没有根本区别；
- 用户为了看结果而来，没有自然理由进入严肃的 Hub；
- 一旦导流效果不佳，整个产品就失去存在理由。

**判断：** 可以保留引流作用，但不适合作为核心定位。

## 版本二：品牌翻译层

**定位：** NBTI 把 VisionTree 抽象的“认知增强、Vision、思考方法”翻译成大众能立即理解的互动体验。

```text
抽象的 VisionTree 理念
  → NBTI 的场景、角色和选择
  → 用户第一次理解“思考方式可以被看见”
```

**优势：**

- 能降低 VisionTree 的理解门槛；
- 角色、名人、场景和舞台视觉都有明确用途；
- 即使用户暂时不进入 Hub，也能理解母品牌在做什么。

**问题：**

- 容易成为一个好看的品牌 Demo；
- 如果只有解释，没有可持续价值，用户仍然只体验一次；
- 可能过度服务品牌叙事，而不是用户真实需求。

**判断：** 适合作为 NBTI 的基础职责，但不足以单独定义产品。

## 版本三：方法发现入口

**定位：** NBTI 让用户从“想了解自己”出发，发现自己常用的思考动作，并第一次体验其他方法。

```text
对自己好奇
  → 看见自己怎样判断
  → 发现另一种思考方法
  → 想到可以用它处理真实问题
  → 进入 Hub
```

**优势：**

- NBTI 自身能交付价值，不只是导流；
- 与 Hub 的连接来自方法和真实问题，而不是广告跳转；
- 与 VisionTree“让用户学会方法”的核心价值一致；
- 能解释为什么要保留场景抉择和名人共演。

**问题：**

- 比普通测试多一层交互和内容设计；
- 需要控制方法解释的重量，避免变成课程；
- 必须验证用户是否真的对“还能怎样想”感兴趣。

**判断：** 这是当前最切实、与 VisionTree 联系最强的定位。

## 版本四：认知游乐场

**定位：** NBTI 是 VisionTree 中长期存在的轻体验区。用户可以不断尝试不同场景、方法、人物视角和朋友对局，而不必每次都带着严肃问题进入 Hub。

```text
轻量探索与娱乐
  ↔ 不同方法的试用
  ↔ 社交比较和内容更新
  → 有需要时进入 Hub 深化
```

**优势：**

- NBTI 不再是一次性活动，而是可持续产品区域；
- 能容纳热点场景、名人方法、双人互动和实验内容；
- 为 VisionTree 提供比严肃工具更轻的日常关系。

**问题：**

- 范围容易失控，变成独立内容平台；
- 需要持续的高质量内容供给；
- 可能与 Hub、Lab 的边界重新混乱；
- 当前阶段建设成本较高。

**判断：** 可以作为长期方向，但不应成为近期起点。

## 推荐定位

建议采用一个主定位、两个辅助作用：

> **主定位：NBTI 是 VisionTree 的方法发现入口。**

它把用户对自我的兴趣，转化为对思考方式和方法的兴趣。用户在 NBTI 中至少看见一种自己的惯用动作，并体验一种不同方法；当这种方法与真实问题产生联系时，再自然进入 Hub。

同时保留：

- **品牌翻译作用：** 用轻量体验解释 VisionTree 在做什么；
- **引流作用：** 通过场景、角色和分享带来新用户。

暂不把“认知游乐场”作为当前承诺，但产品结构应允许未来向它扩展。

## 一句话关系

```text
NBTI 让用户发现方法
→ Hub 让用户把方法用于真实问题
→ Tree 让方法和判断在长期使用中沉淀、修订和复用
```

## 团队校准句

以后判断一个 NBTI 功能是否值得做，可以先问：

> 它只是让用户更想拿到结果，还是让用户更容易发现一种可以继续使用的思考方法？

前者只有引流价值，后者才符合推荐定位。
