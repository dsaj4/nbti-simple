# NBTI 产品形态探索

## 0. 结论摘要

基于 [positioning-exploration.md](positioning-exploration.md) 的定位，本文件建议对 NBTI 进行“旅行改造”，采用以下产品形态：

> **一段多幕选择式思维旅行。用户带着一个待回答的问题出发，在沿途场景中作出选择，遇见代表不同方法的名人或原创角色，获得可以继续使用的思维收获，并由整段路线共同生成自己的结局。**

可以用 RPG 作为结构类比：用户拥有旅程、扮演、相遇、选择、获得和结局，但不需要战斗、等级、装备或开放世界。NBTI 真正的成长不是数值变强，而是获得一种方法，并在后续选择中知道何时使用、何时改造、何时拒绝。

“思维共演”仍是每一幕的核心玩法，“多幕旅行”则是把多次共演组织成一段完整体验的产品外壳。最小完整体验不是“答题—计分—拿类型”，而是：

```text
带着一个待回答的问题出发
  → 在第一幕作出自然选择
  → 沿途遇见方法型人物
  → 通过共演获得方法收获
  → 在后续幕使用、拒绝或改造收获
  → 选择与收获改变行进路线
  → 抵达由整段路径生成的个人结局
  → 将最有用的方法带入 Hub 的真实问题
```

现有 Editorial Stage 报告页可以继续作为重要资产，但它的角色应从“测试报告”调整为“终幕结局页”：呈现用户抵达哪里、为何走到这里、带走了什么，以及还有哪条未走的路。

这里的“旅行”描述完整体验结构，不表示当前应制作大型 RPG。近期最小实现仍是一段由团队策划的短旅程，采用有限分路和可汇合路线，避免分支内容指数增长。

## 1. 文件目的

本文回答以下问题：

1. 什么产品结构才能真正实现 NBTI 的新定位？
2. 哪一个对象应成为产品的最小内容和数据单元？
3. 趣味、身份、方法觉察、传播和 VisionTree 协同如何出现在同一条用户路径中？
4. 一次性测试、场景流、互动故事、双人玩法和创作平台分别有什么取舍？
5. 当前最切实可验证的最小完整形态是什么？

本文描述产品结构与演化方向，不规定具体技术栈、视觉稿、上线日期或开发排期。

## 2. 从定位反推产品要求

如果 NBTI 的价值是“看见自己怎样想，也发现还能怎样想”，产品形态必须同时满足以下条件。

### 2.1 必须保留低门槛进入

用户首先是为了好奇、趣味和自我表达而来，不是为了参加课程。第一个有效选择应在很短时间内发生，不能先阅读方法说明、注册账户或填写大量背景。

### 2.2 必须产生可观察行为

产品不能只让用户同意抽象陈述，例如“我重视逻辑”。用户需要在存在取舍的具体现场中作出选择，系统才有材料解释其思维动作。

### 2.3 必须发生方法介入后的再判断

普通测试也可以使用情景题。NBTI 的差异不在题目形式，而在于用户能否亲自体验另一种方法如何改变注意点和判断依据。

### 2.4 单个场景必须独立交付价值

每个场景都应让用户获得一次完整的小觉察，不能要求完成几十道题后才看到意义。这既降低退出成本，也为分享、回访和内容持续更新提供基础。

### 2.5 多个场景必须形成新价值，而不只是累积分数

连续体验应帮助用户看到并感受到：

- 哪些思维动作跨场景反复出现；
- 哪些动作只在特定压力或关系条件下出现；
- 哪些方法曾让用户有效地重新判断；
- 用户的理由和边界如何变化；
- 早先的选择和收获如何改变后续路线。

如果多做场景只让类型分数更精确，或者只把下一道题包装成“下一站”，产品仍然停留在传统测试逻辑。

### 2.6 结局与旅途回顾必须有路径证据支撑

角色和舞台继续提供情绪价值与传播性，但结局中的每项描述都应能回到用户真正走过的场景、选择、理由、相遇和方法使用。

### 2.7 与 Hub 的连接必须由用户意图触发

当用户想到一个真实问题时，产品可以把刚体验的方法和相关判断带入 Hub。不能在每个结果后机械导流，也不能把 NBTI 扩张成一个简化但重复的 Hub。

### 2.8 必须有明确的出发与抵达

旅行不能只是一串主题相似的场景。开场需要给用户一个愿意继续走下去的问题、目标或邀请，终幕则需要回应这个出发点。用户应知道自己为何启程，也能理解最终结局与沿途选择的关系。

### 2.9 旅途收获必须在后续幕可使用

人物相遇不能只解锁图鉴或文案。每次重要相遇都应让用户获得一个可操作的方法动作，例如检查隐藏前提、比较机会成本或寻找反证；后续至少有一幕允许用户主动使用、拒绝或改造它。

### 2.10 结局必须来自路线，而不是隐藏类型

结局应综合用户走过的场景、关键理由、使用过的方法和放弃的路径。它不应只是把累计分数映射回“赛博判官”等固定类型，也不应存在明显的最好结局和最差结局。

## 3. 产品的最小原子：一次“判断试演”

推荐继续把每一幕的最小互动单元定义为**判断试演**，而不是题目、类型或报告卡。完整产品则由多幕判断试演、人物相遇、方法收获、路线变化和个人结局共同构成。

一次完整判断试演包含七个部分：

| 部分 | 用户行为 | 产品作用 |
| --- | --- | --- |
| 现场 | 阅读一个短而有冲突的情境 | 建立代入感和真实取舍 |
| 初始判断 | 在合理选项中作出选择 | 记录未经提示的自然反应 |
| 判断依据 | 选择最接近自己的主要理由，必要时补充 | 区分相同选项背后的不同思路 |
| 动作镜像 | 看见系统对本次可观察动作的中性描述 | 形成第一层自我觉察 |
| 方法共演 | 回答一种方法提出的关键问题 | 看见另一种观察现场的方式 |
| 再次判断 | 坚持、调整或推翻原选择，并确认理由 | 形成有效再判断 |
| 旅途印记 | 获得前后变化、方法和边界的简明总结 | 完成理解、记忆，并写入旅程状态 |

### 3.1 为什么不是“题目”

题目只负责采样，无法独立交付认知价值。判断试演同时包含行为、解释和方法对照，是 NBTI 区别于普通测试的最小闭环。

### 3.2 为什么需要判断依据

只记录用户选了什么会产生大量误判。例如两个人都选择“暂不发布”，一个可能因为证据不足，另一个可能因为担心关系受损。NBTI 要描述思维方式，就必须尽量区分选择与理由。

为了控制负担，首版可以使用经过设计的理由选项，并允许“都不符合”或简短补充，而不是强迫用户输入长文本。

### 3.3 为什么方法介入只能很轻

趣味入口的注意力预算有限。一次试演只应引入一个关键动作，例如：

- 先检查问题中的隐藏前提；
- 比较不行动的机会成本；
- 询问这个决定是否可逆；
- 从受影响最大的人视角重看；
- 寻找能够推翻当前判断的证据。

它应让用户立即用一次，而不是先讲完整理论史。

## 4. 核心用户循环

### 4.1 单场景循环

```text
被一个现场吸引
  → 迅速作出选择
  → 发现自己刚才先看见了什么
  → 被另一种方法追问
  → 形成更清楚的再判断
  → 得到可带走的旅途印记
```

单场景循环解决的是“这次体验是否值得”。理想完成时间应以短体验为目标，但具体时长需要原型测试，不在本文预设硬阈值。

### 4.2 旅行循环

```text
完成当前一幕
  → 看见选择产生的局部后果
  → 遇见人物并获得方法收获
  → 选择下一站或被路线带向下一幕
  → 在后续幕再次使用或拒绝收获
  → 抵达个人结局
```

旅行循环解决的是“NBTI 为什么不是一套披着剧情外衣的测试”。用户继续的动力不仅是想知道自己是什么类型，还包括想看见选择造成什么变化、会遇见谁、能够带走什么，以及最终抵达哪里。

### 4.3 方法循环

```text
在一个场景中第一次使用某种方法
  → 在另一个不同场景中再次遇见或主动选择它
  → 减少提示后自行完成关键动作
  → 理解方法的适用条件和边界
```

方法循环是 NBTI 与 VisionTree 长期价值最重要的连接，但首版只需证明用户愿意再次尝试，不必在趣味入口内完成系统教学。

### 4.4 结局循环

```text
抵达一个个人结局
  → 回看形成结局的关键选择、人物和收获
  → 看见一条未走路线或不同方法的可能
  → 分享结局或重新启程
```

结局既要提供完成感，也要保留开放性。它可以回答“这次旅程中的我成为了怎样的行路者”，但不能宣称发现了用户固定的人格本质。重新启程的价值应来自探索另一条路径，而不是刷出更高等级。

### 4.5 真实问题循环

```text
场景让用户联想到自己的问题
  → 用户选择“用这个方法看看我的问题”
  → NBTI 带着方法和必要上下文进入 Hub
  → Hub 重新确认目标、背景、证据和责任边界
  → 运行完整 Vision 过程
```

真实问题循环必须由用户主动触发。趣味选择不能直接替代真实问题中的判断。

## 5. 候选产品形态比较

| 产品形态 | 趣味吸引力 | 独特价值 | 重复使用 | VisionTree 协同 | 内容成本 | 当前建议 |
| --- | --- | --- | --- | --- | --- | --- |
| 一次性类型测试 | 高 | 低 | 低 | 低 | 低 | 仅作过渡，不作为终局 |
| 无限场景选择流 | 高 | 中低 | 高 | 中 | 中 | 缺少方法介入时容易浅化 |
| 多幕思维旅行 | 很高 | 高 | 高 | 高 | 高 | 推荐完整产品形态，首版控制规模 |
| 双人默契或对战测试 | 高 | 中 | 中 | 中 | 中 | 适合作为传播模式，不作主产品 |
| 连续式思维试演平台 | 高 | 高 | 高 | 高 | 中高 | 作为旅行内容与系统底座 |
| 开放式场景创作平台 | 潜在高 | 高 | 高 | 高 | 很高 | 长期可能，当前过早 |

### 5.1 为什么不继续以一次性测试为主

一次性测试最容易承接现有报告页，也最容易让用户理解，但它的增长依赖不断发布新类型或新系列，用户完成后没有自然的第二次价值。更重要的是，它会让团队持续把资源投入分类、评分和包装，而不是 NBTI 真正独特的再判断机制。

### 5.2 为什么选择旅行，而不是完整 RPG

旅行结构可以把场景选择、人物共演、方法获得和个人结局统一起来，也比孤立试演更能产生代入感与完成动力。因此，它适合作为 NBTI 的完整产品形态。

但 NBTI 不应照搬大型 RPG 的全部系统。首版只采用对认知体验有直接价值的部分：

- 用户扮演一名出发者；
- 旅程由多个幕组成；
- 选择会改变局部事件和后续路线；
- 重要人物带来方法收获；
- 收获可以在后续使用；
- 路径共同形成个人结局。

战斗、等级、装备、开放世界、复杂支线和资源经营暂不进入范围。这能保留旅行感，同时避免团队过早转型为重内容游戏工作室。

### 5.3 为什么不先做双人产品

朋友比较具有天然传播力，但如果单独成立，产品很容易退化为默契、关系匹配或观点站队。双人模式应建立在单人判断试演已经成立的基础上，让双方比较“为何这样想”，而不是只比较答案是否一致。

### 5.4 为什么不先开放 UGC

有效场景需要平衡冲突、合理选项、方法适用性、反馈边界和安全风险。过早开放创作会迅速产生常识题、价值诱导、伪方法和名人模仿内容。

首批内容应由团队策划和审核；只有当原子结构、质量标准和审核机制稳定后，才讨论创作者工具。

## 6. 推荐主形态：多幕选择式思维旅行

### 6.1 正式定义

> NBTI 是一段由多幕场景组成的选择式思维旅行。用户带着一个问题出发，在途中作出判断、遇见代表不同方法的人物、获得并使用思维收获；选择与收获共同改变路线，最终形成一个有个人证据、但不固定用户本质的结局。

“旅行”是完整体验结构，“思维共演”是每一幕的核心玩法，“连续式思维试演系统”是支撑内容复用的后台底座。三者不是彼此竞争的产品方向。

### 6.2 产品结构

```text
NBTI
  ├─ 一段旅程
  │    ├─ 序幕：选择出发理由
  │    ├─ 第一幕：自然判断
  │    ├─ 相遇：人物共演与方法收获
  │    ├─ 第二幕：路线分化
  │    ├─ 第三幕：主动使用或拒绝收获
  │    └─ 终幕：个人结局
  ├─ 旅途回顾：路线、选择、相遇与收获
  ├─ 单幕分享与朋友进入同一路口
  └─ 使用旅途收获处理真实问题 → VisionTree Hub
```

### 6.3 旅程主题

每段旅程需要一个能够贯穿始终的出发问题，而不是把不相关的测试题串起来。候选主题可以围绕：

- 穿过信息迷雾，找到自己愿意相信什么；
- 在关系与原则之间，决定怎样同行；
- 面对未知道路，判断何时行动、何时等待；
- 在多个可能世界中，选择自己愿意建设的一个；
- 在时间耗尽前，决定什么值得保留。

首发旅程应低风险、易代入、没有明显正确答案，同时能够容纳多种思考方法。医疗、法律、金融和心理危机场景不适合作为早期趣味内容。

### 6.4 判断轨迹

判断轨迹不是一个总分，而是多个样本之间的关系。它可以回答：

- 用户经常首先使用哪些动作；
- 哪些情境会让用户改变动作；
- 哪些判断依据最常出现；
- 哪些方法曾让用户修正理由；
- 用户在哪些场景中主动拒绝了系统建议。

只有在样本足够且用户同意保存时，产品才生成跨场景总结。首版不需要建立永久用户画像。

### 6.5 旅行状态

旅行需要记录会真实影响后续体验的少量状态：

| 状态 | 作用 |
| --- | --- |
| 路线 | 用户经过哪些地点和事件 |
| 关键选择 | 哪些决定改变了后续局面 |
| 判断依据 | 用户为什么这样选择 |
| 人物相遇 | 用户遇见了哪些方法型人物 |
| 方法收获 | 用户获得了哪些可操作的方法 |
| 使用记录 | 用户何时使用、拒绝或改造了收获 |
| 未走之路 | 哪些重要路线因选择而关闭或保留 |

首版不需要复杂数值面板。这些状态主要用于后续场景变化、结局生成和旅途回顾，而不是让用户追求最优配点。

### 6.6 个人结局

个人结局至少包含：

- 用户最终抵达的地点、身份或局面；
- 形成这一结局的两至三个关键选择；
- 对路线影响最大的一次人物相遇；
- 用户真正使用过的一项方法收获；
- 用户坚持、放弃或仍未回答的问题；
- 一条清晰但不强迫的未走路线。

结局之间应是不同价值取舍和思考路径，不设置明显的好坏等级。结局可以使用角色化、文学化表达，但必须能追溯到用户的旅途记录。

### 6.7 前台体验与后台系统

为了同时守住趣味和方法可信度，推荐把产品明确分成两个层次。

**用户前台是多幕思维旅行：**

- 以出发目标、地点变化、故事冲突和快速选择建立代入感；
- 不要求用户理解 Vision、Skill 或认知资产等内部术语；
- 方法通过人物相遇、一次关键追问或实际操作出现；
- 旅途收获在后续幕中可以主动使用；
- 结局优先回答“我怎样走到这里、带走了什么”，再解释方法名称。

**内容后台是方法化场景系统：**

- 定义场景希望观察的动作和判断依据；
- 约束每种方法的目标、步骤、适用条件和可能遗漏；
- 保存初始判断、介入、再判断和用户理由之间的关系；
- 保存路线、人物相遇、收获使用和结局条件之间的关系；
- 支持内容审核、偏差检查、效果评估和后续复用；
- 为进入 Hub 时提供必要但最少的上下文，而不是传递人格标签。

这一分层意味着用户感受到的是轻巧的戏剧体验，团队维护的却必须是严谨的场景与方法结构。不能为了后台严谨把前台做成教学工具，也不能为了前台趣味让后台只剩随意编题和角色文案。

## 7. 场景设计规范

### 7.1 一个有效场景必须具备

- 一个用户能够迅速理解的具体现场；
- 至少两个都能被合理辩护的选择；
- 一项真实取舍、信息缺口或价值冲突；
- 能区分不同判断依据的理由设计；
- 至少一种适用但不直接给答案的方法；
- 允许用户坚持、修改、拒绝或补充；
- 一段描述行为和边界、而非评价人格的反馈。

### 7.2 应避免的场景

- 存在明显道德正确答案的伪选择；
- 用极端选项逼用户选择预设答案；
- 依赖专业知识却不给必要信息；
- 把高风险现实建议包装成趣味选择；
- 通过羞辱、自私或愚蠢等评价制造戏剧性；
- 只有选择，没有解释和再判断价值；
- 为了匹配某个预设类型而反向编题。

### 7.3 反馈原则

反馈应优先使用：

- “在这个场景中，你先……”；
- “这个选择主要依赖……”；
- “当……成为约束时，你调整了……”；
- “这种方式有助于……，但可能暂时忽略……”；
- “另一种方法让你补充检查了……”。

反馈应避免：

- “你就是……”；
- “真正的你……”；
- “你的大脑天生……”；
- “这说明你不适合……”；
- “只有少数聪明人才会这样选”。

## 8. 方法共演系统

### 8.1 共演者的本体是方法动作

共演者不是聊天人格，而是一种可检查的思考动作。每位共演者至少需要定义：

| 字段 | 说明 |
| --- | --- |
| 方法目标 | 它帮助用户补看什么问题 |
| 关键动作 | 用户需要实际完成的一步 |
| 适用条件 | 在什么场景下值得使用 |
| 不适用条件 | 何时会增加负担或产生误导 |
| 介入问题 | 本场景中最少但有效的一次追问 |
| 可能遗漏 | 该方法本身不擅长处理什么 |

### 8.2 名人和历史人物的使用方式

人物可以作为方法的文化化外衣，例如用历史人物帮助用户记住一种追问或观察动作。但必须满足：

- 方法能够脱离人物独立解释；
- 只使用公开可见、可合理归纳的方法线索；
- 不模拟人物真实内心、语气或对现代私人问题的判断；
- 不暗示授权、参与或认可；
- 优先采用历史文化人物或原创角色，谨慎使用现代公众人物。

人物不应作为随机彩蛋平均分配。更合理的出现方式是：用户当前路线暴露了某个尚未检查的前提、冲突或盲点，相应人物才在这一站出现，并通过其代表的方法帮助用户重新看见现场。不同路线可以遇见不同人物；即使遇见同一人物，也可以因为此前选择不同而获得不同侧面的收获。

### 8.3 共演后的有效结果

系统不以用户改选为目标。共演后的结果可以是：

- `坚持`：选择不变，理由更完整；
- `修正`：选择不变，但条件或边界改变；
- `改选`：新信息或新标准改变了选择；
- `拒绝`：用户判断该方法不适用于当前现场；
- `未决`：用户意识到现有信息不足，暂不下结论。

这五种结果都应被视为有效判断，而不是按“是否接受系统建议”评分。

## 9. 终幕结局与旅途回顾

### 9.1 终幕页面的新职责

现有舞台式报告可以改造成终幕结局页，承担四个任务：

- 给用户“我确实抵达了某处”的完成感；
- 把抽象动作转化为有身份感的行路者或终点角色；
- 回顾形成结局的路线、选择、相遇和方法收获；
- 生成适合回看、分享和再次启程的视觉结果。

结局页不宣判固定人格，也不应脱离旅途证据单独生成。旅程本身是价值主体，终幕负责收束而不是替代过程。

### 9.2 建议的信息层级

1. **抵达结局**：用户最终来到的地点、身份或局面。
2. **出发回应**：这个结局怎样回答序幕提出的问题。
3. **关键路标**：形成结局的两至三个决定及其理由。
4. **重要相遇**：哪位人物和哪种方法最影响后续路线。
5. **随身收获**：用户真正使用过、可以继续带走的方法。
6. **未决之问**：用户仍然坚持、放弃或没有回答什么。
7. **未走之路**：另一条值得探索的路线，但不暗示当前结局较差。
8. **安全说明**：结局来自本次旅途，不是人格诊断或能力评级。

### 9.3 角色与维度

终点角色可以继续使用“赛博判官”等鲜明表达，维度也可以帮助解释不同动作。但应遵守：

- 角色由旅途中的选择、理由和收获使用支持；
- 维度只作为旅途回顾的辅助，不作为隐藏结局分数；
- 不把单次波动伪装成稳定人格变化；
- 没有真实常模时，不展示精确稀有度和人群百分位；
- 用户可以回看自己如何一步步抵达这个角色与结局。

## 10. 分享与社交形态

### 10.1 第一分享物：旅途印记

单幕分享物不是只有角色名的结果卡，而是一张简洁的旅途印记：

- 场景中的关键冲突；
- 用户的初始选择；
- 共演方法提出的问题；
- 用户最终坚持、修正或改变了什么；
- 一句由用户确认的理由；
- 邀请朋友进入同一现场的入口。

它让分享内容从“我是哪类人”升级为“我为什么这样判断”。

### 10.2 第二分享物：个人结局舞台

终幕结局仍然适合截图和身份表达，但分享版本应带有旅程提示，例如“我在迷雾旅程中抵达的结局”，避免被理解为永久人格标签。

### 10.3 朋友挑战

朋友挑战可以复用同一个判断试演：双方先独立选择，再比较选择、理由和方法介入后的变化。

比较重点应是：

- 我们注意到了不同的什么；
- 相同选择背后的理由是否不同；
- 哪种方法分别改变了我们的判断。

它不应退化为默契分、关系优劣或谁更聪明的排名。

## 11. 与 Hub、Lab 和 Tree 的产品连接

### 11.1 Hub

NBTI 可以拥有独立的公开入口、旅程主题和传播页面，但账户与长期数据能力原则上应与 VisionTree Hub 连续，而不是形成另一个主产品闭环。

进入 Hub 的入口必须具体，例如：

> 你刚才用“检查隐藏前提”重新判断了这个场景。要不要用同一步处理一个你正在面对的真实问题？

这比通用的“查看更多”“进入 VisionTree”更能保持意图连续。

### 11.2 Lab

Lab 更适合作为内部能力，负责：

- 场景原型测试；
- 方法适用性和边界校验；
- 选项偏差与诱导检查；
- 反馈文案审核；
- 不同介入强度的实验；
- 失败样本和认知安全复盘。

它不需要在用户侧成为与 NBTI、Hub 平级的复杂入口。

### 11.3 Tree

NBTI 的趣味选择默认不直接进入 Tree。合理的渐进关系是：

```text
匿名或临时判断样本
  → 用户选择保留旅途轨迹
  → 用户把一种方法用于真实问题
  → Hub 形成包含目标、依据和用户判断的认知条目草稿
  → 用户决定是否进入 Tree
```

这样既保护隐私，也避免把低风险游戏行为过度解释为用户的长期认知画像。

## 12. 最小完整产品形态

当前最值得验证的不是一个庞大平台，而是一段能够证明核心机制的完整短旅程。

### 12.1 建议范围

- 一段有明确出发问题和终点回应的短旅程；
- 三至四幕具有不同约束的主要场景；
- 两至三位代表可复用方法的名人或原创角色；
- 每幕都有初始判断、主要依据、人物共演和再次判断；
- 每次重要相遇形成一项方法收获；
- 至少一项早期收获能在后续幕主动使用、拒绝或改造；
- 两次有限分路，后续允许汇合，以控制内容规模；
- 三至五个没有高低等级的个人结局；
- 每幕生成旅途印记，终幕生成有路径证据的结局页；
- 至少一个邀请朋友从同一路口出发的入口；
- 至少一个基于当前方法、由用户主动触发的 Hub 真实问题入口。

具体数量用于证明“选择影响路线、相遇带来收获、收获影响后续、路径形成结局”这一完整链条，同时控制首轮内容成本，仍需通过原型测试调整。

### 12.2 暂不需要

- 固定的十六型或大型人格宇宙；
- 自由生成任意题目和报告；
- 开放式 UGC 或创作者分成；
- 战斗、等级、战力、装备稀有度和资源经营；
- 开放世界、大量支线和不可汇合的复杂分支树；
- 签到和收藏驱动的游戏化系统；
- 强制登录；
- 完整长期画像；
- 自动写入 Tree；
- 多人实时房间；
- 为所有 Vision 方法建立百科库；
- AI 名人聊天。

### 12.3 为什么这是最切实的形态

它能够最大限度复用当前已经存在的场景选择、角色舞台、报告数据结构和分享资产，同时把新增工作集中在真正需要验证的差异化机制上：

- 用户是否愿意说明判断依据；
- 一次轻量方法介入是否能产生有效再判断；
- 多幕选择、人物相遇和方法收获能否形成比固定类型更有价值的个人结局；
- 用户是否愿意把方法迁移到真实问题。

它不要求团队先建设内容平台、账户体系、长期 Tree 或复杂 AI 生成能力。

## 13. 产品演化路径

### 阶段一：证明判断试演成立

目标是证明单场“初始判断—方法共演—再次判断”比普通情景题多产生了可理解的用户价值。

### 阶段二：证明短旅行成立

把三至四个判断试演组织成有出发、相遇、分路和结局的短旅程，验证用户是否感到自己在前进，而不是连续答题。

### 阶段三：证明收获影响后续与结局

验证人物带来的方法是否会被用户记住和主动使用，以及早期选择、方法收获和后续判断是否真正改变路线与结局。

### 阶段四：证明社交传播不稀释认知价值

加入同路口出发、结局比较和旅途印记传播，检查用户分享的是路线、理由与方法，还是重新退化为结局优越感和观点站队。

### 阶段五：证明与 Hub 的真实迁移

让用户把体验过的方法带入自己的真实问题，验证 NBTI 是否真正承担了方法发现入口，而不是只带来低意图流量。

### 阶段六：扩展内容供给

只有在场景标准、方法规范、审核机制和核心指标稳定后，才考虑创作者工具、合作系列或受控 UGC。

## 14. 验证指标与失败条件

### 14.1 原子体验指标

- 首场完成率；
- 判断依据选择或补充完成率；
- 方法介入后的有效再判断率；
- 用户能否准确复述自己刚才使用的动作；
- 用户能否说明坚持或改变的原因。

“有效再判断”不等于改选。只要理由、条件、边界或适用性判断发生了实质确认或修正，就可以构成有效再判断。

### 14.2 连续价值指标

- 完成一幕后继续前往下一幕的比例；
- 旅程完成率；
- 用户能否理解早期选择如何影响后续路线；
- 用户是否在后续幕主动使用、拒绝或改造过方法收获；
- 用户能否识别跨场景的稳定动作和条件性变化；
- 在减少提示后再次使用同一方法的表现；
- 结局页回看、分享和重新启程意愿。

### 14.3 产品体系指标

- 用户是否由场景自然联想到真实问题；
- 用户是否主动选择把方法带入 Hub；
- 进入 Hub 后是否完成了至少一个有效判断节点；
- 后续是否在不同问题中再次使用该方法。

### 14.4 明确失败条件

出现以下情况时，不应继续通过增加角色、题量或视觉包装掩盖问题：

- 用户完成后只记得类型名，无法说明任何思维动作；
- 用户认为自己只是在连续答题，路线变化没有真实感；
- 名人相遇只被记作彩蛋，用户说不出获得了什么方法；
- 旅途收获从未在后续幕产生作用；
- 结局只是隐藏总分对应的固定类型；
- 方法共演被理解为标准答案或说教；
- 用户为了迎合系统而机械改选；
- 多场景体验只提高分数精度，没有产生条件性认识；
- 结局描述无法追溯到具体路线、选择和收获；
- 分享主要依赖稀有度、优越感或负面标签；
- Hub 跳转率存在，但用户进入后没有真实问题和判断意愿；
- 内容生产成本高到无法持续提供新系列。

## 15. 产品原则

后续所有产品设计可以用以下原则校准：

1. **先让用户判断，再解释方法。** 不用教学前置消耗趣味动机。
2. **描述行为，不定义本质。** 所有结论都能回到具体情境证据。
3. **允许坚持，也允许拒绝。** 系统不以改变用户答案证明自己有效。
4. **一次只介入一个关键动作。** 保持低门槛，避免把场景变成课程。
5. **角色服务于理解，不能压过方法。** 用户应记得角色，也应知道它代表什么动作。
6. **跨场景展示变化，不追求伪精确。** 条件性轨迹比固定高分更有价值。
7. **单场独立有价值，连续体验产生新价值。** 不用长题量绑架用户完成。
8. **分享判断过程，不制造类型优越感。** 社交机制应帮助比较理由。
9. **趣味样本不自动等于认知资产。** 保存和进入 Tree 必须由用户主动决定。
10. **NBTI 负责发现，Hub 负责真实应用。** 两者连续，但不重复建设。
11. **旅行结构服务于选择后果。** 如果路线不因选择和收获而变化，就不要用旅行包装掩盖线性题组。
12. **结局负责收束，不负责定型。** 用户抵达的是本次旅程的答案，不是永久人格。

## 16. 本轮建议决策

建议团队把以下形态作为后续产品探索的主方向：

> **NBTI 从一次性思维类型测试，演化为多幕选择式思维旅行；以判断试演为单幕原子，以名人或原创角色的方法共演形成旅途收获，以选择和收获改变路线，并由整段路径生成用户自己的结局。**

这项决策并不要求废弃当前报告页。相反，它为当前视觉和角色资产提供了更稳定的产品位置：报告页成为终幕结局页，负责把路线、关键选择、人物相遇和方法收获转化为有身份感、可解释、可分享的抵达时刻。

在这一方向得到用户验证之前，不建议优先扩充大量类型、构建开放创作平台、加入战斗养成与复杂分支，或建设独立于 Hub 的长期账户与资产体系。
